# Wolfenstein-style FPS

A single-level, procedurally generated first-person maze shooter, and the tooling that
verifies it. This file is the project's glossary and nothing else: what the words mean, and
which word to use when several would do. Decisions live in `DECISIONS.md`, requirements in
`specs/`, and rules in `.specify/memory/constitution.md`.

## Language

### The game

**Run**:
One life of play, from spawn or the most recent restart until the player dies or rides the
elevator. Its phases are `playing`, `dead`, `exiting` and `complete`.
_Avoid_: game, session, life

**Level**:
The single 64×64 tile grid the game ships, together with the marker tables that populate
it. There is exactly one, and it is generated by code like everything else.
_Avoid_: map, stage, world

**Tile**:
One cell of the level grid, addressed by integer `x` and `z`. A player stands at a tile's
centre; a coordinate that is not a tile centre is a position, not a tile.
_Avoid_: cell, square, block

**Guard**:
One hostile occupant of the level, spawned from a marker, driven by a state machine and
drawn as an eight-angle billboard.
_Avoid_: enemy, NPC, monster, mob

**Secret**:
A push-wall the player opens with the interact command, revealing space the level does not
otherwise offer. Indistinguishable from the wall it sits in until pushed.
_Avoid_: hidden door, easter egg

**Treasure**:
A pickup that scores and counts toward a run's treasure axis. Distinct from health and
ammunition pickups, which restore rather than score.
_Avoid_: loot, gold, collectible

**Interact command**:
The single command bound to more than one key that resolves every use in the game — doors,
secrets, pickups and the elevator. There is one command path, never a second handler.
_Avoid_: use key, action button, activate

**Rating**:
The band a completed run earns from the mean of its kill, secret and treasure percentages.
A property of a finished run, not of a player.
_Avoid_: score, grade, rank

**Diagnostics**:
The `window.__diag` object the running page publishes: the single channel through which
anything outside the browser learns what the game is doing.
_Avoid_: debug info, telemetry, stats

### Verification

**Gate**:
A command that decides whether work may land, declared in `ergane.yaml`. Green means every
gate passed; a gate is never weakened to make work pass.
_Avoid_: check, CI step, build

**Smoke harness**:
The headless browser pass that drives the built page and reads diagnostics back. It is what
makes "it compiled" and "it works" different claims.
_Avoid_: integration test, e2e

**Playthrough**:
One invocation of the recorded playtest command: up to three attempts, and exactly one
record. What a person watches to accept the game.
_Avoid_: playtest run, UAT run, demo

**Attempt**:
One loaded page driven from spawn until it completes or fails. The unit a recording, a
timeline and a console capture each belong to. A playthrough may spend several.
_Avoid_: retry, try, iteration

**Objective**:
One thing the level offers to be cleared — a guard, a secret, a treasure, a key or the exit
— derived from the level's own tables and confirmed by the counter that owns it.
_Avoid_: goal, task, waypoint, target

**Leg**:
The path between two objectives, routed by the game's own pathfinder and walked with real
input. Objectives are what to do; legs are how the agent gets there.
_Avoid_: segment, route step, path

**Hard criterion**:
A condition whose failure fails an attempt and may spend another: the run reached
`complete`, no error was recorded, no page error was thrown.
_Avoid_: assertion, must-pass, blocker

**Soft criterion**:
A measured value that is reported and never fails an attempt — completion percentages, the
rating, the frame rate, the duration. Measured, never fatal.
_Avoid_: warning, soft assertion, metric

**Verdict**:
The outcome of a playthrough as decided by its hard criteria, carrying the number of
attempts it took. A pass on the third attempt and a pass on the first are different
verdicts.
_Avoid_: result, status, outcome

**Playtest record**:
The output directory one playthrough writes: per-attempt recordings and console captures,
the machine-readable result and the human-readable report. Build output, in the sense
`dist/` is — never a repository asset.
_Avoid_: artifact, output, report folder

**Timeline**:
The ordered events of one attempt, each stamped with its offset from that attempt's
recording start, so any event named in a report can be found in the video.
_Avoid_: log, trace, event list

**Harness fault**:
A failure that is not a fact about the game — a refused pointer lock, a browser that would
not launch, a page that never loaded. Retryable, and never reported as a gameplay result.
_Avoid_: flake, infrastructure error, glitch
