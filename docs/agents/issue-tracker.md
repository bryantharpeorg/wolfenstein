# Issue tracker

This repository is built by the Ergane factory, and its nodes run sandboxed with no
network credentials and no ability to run slash commands. **Do not try to file an
issue, and do not tell the operator to run a setup command.**

Where findings go instead, in order of preference:

1. **Your node's verdict.** A review finding that should block the work belongs in the
   verdict you return. Ergane's own instructions to your node are authoritative and
   override anything a skill says about where to record findings.
2. **`DECISIONS.md`** — one line — when you settled an open design fork with a
   defensible default. See Constitution Article VIII.
3. **An escalation** when you cannot proceed and need the operator. Say so plainly and
   stop; do not invent a tracker.

There is no GitHub issue tracker wired to this repo yet. When one exists, this file is
what tells the skills where it is.
